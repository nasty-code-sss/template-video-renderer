# Бриф

Заполнен 16.09.2026. Заказчика у проекта нет: это демонстрационный проект.
Поэтому пункты, которые обычно приходят от заказчика, заполнены предположениями,
и каждое предположение названо вслух.

## Ядро

Собирает готовый видеофайл из описания сцен и шаблона оформления, без ручного монтажа.

Проверка на правильность ядра: если сборка видео не работает, проект бессмысленен,
чем бы его ни обвешали. Пакетный прогон, отчёты и предпросмотр пользу без неё не дают.

## Тип и платформа

CLI на Python 3.12. Работает на Windows 11 и на Linux, потому что единственная
внешняя зависимость это FFmpeg, а он есть под обе системы. Проверяется на Windows.

## Пользователь и запуск

Один человек запускает командой в терминале и получает файл mp4.
Второй пользователь это робот или скрипт: тот же вызов, но пачкой по списку данных.
Графического интерфейса нет и не планируется: он не относится к ядру.

## Сценарии по шагам

1. Рендер одного ролика.
   Пользователь готовит JSON со сценами и запускает `render`.
   Ожидание: появляется mp4 заданного разрешения и длительности, в кадре текст
   и картинки из JSON, между сценами переход из шаблона.

2. Смена оформления без правки данных.
   Пользователь меняет шаблон (цвет, шрифт, длительность сцены) и запускает то же самое.
   Ожидание: ролик пересобирается с новым оформлением, данные не тронуты.

3. Пакетный прогон.
   Пользователь даёт папку с несколькими JSON и запускает `render` по каждому.
   Ожидание: столько же файлов mp4, единый стиль, один упавший ролик не роняет остальные.

4. Понятная ошибка вместо мусора.
   В JSON нет обязательного поля или картинка не найдена.
   Ожидание: работа останавливается до рендера, в сообщении сказано, какая сцена
   и какое поле виноваты. Битого mp4 не остаётся.

## Данные

Своей базы нет, состояние между запусками не хранится.
На входе файлы пользователя: JSON проекта, картинки, шаблон YAML.
На выходе mp4 в указанной папке. Персональных данных нет.
Промежуточные кадры пишутся во временную папку и удаляются после сборки.

## Внешние системы

FFmpeg, вызывается как внешний процесс. Документация: https://ffmpeg.org/ffmpeg.html
Сетевых обращений нет вообще: всё считается локально.

## Доступы, которые нужны от заказчика

Никаких. Проект не ходит в сеть и не требует ключей.

## Где крутится

Локально на машине пользователя. Позже может уехать на сервер как часть робота,
для этого достаточно установленного FFmpeg.

## Ограничения

Срок не назначен.
Стек выбран по замерам на машине разработки от 16.09.2026: Python 3.12, Pillow,
FFmpeg 8.1.2. 3D в проект не входит сознательно: машина без дискретной видеокарты
рендерит 3D-анимацию часами, это измерено, а не предположено.

## Готово это

Команда `render` из чистой установки собирает демонстрационный ролик,
ролик открывается в проигрывателе, в кадре ровно то, что задано в JSON,
а смена шаблона меняет картинку без правки данных.
Проверка глазами обязательна: собранный файл проверяется покадрово, а не по факту,
что процесс завершился без ошибки.

## Открытые вопросы

Нет. Всё, что могло бы стать вопросом про оформление (формат кадра, шрифты, цвета,
переходы), вынесено в конфиг и шаблон, поэтому ответ не требуется: параметр меняется,
а не согласовывается.

## Предположения, по которым иду

1. Ролики нужны и вертикальные, и горизонтальные. Поэтому разрешение задаётся
   в конфиге, а не выбирается один раз.
2. Озвучки голосом в ядре нет: локального движка синтеза речи на машине не стоит,
   а ставить его до того, как ядро работает, рано. Звуковая дорожка при этом
   поддерживается: фоновую музыку можно подложить файлом.
3. Кадры рисуются на Pillow, а не в браузере. Причина: Pillow уже стоит и на замере
   16.09.2026 дал 22 кадра в секунду на 1080p, этого достаточно. Вариант с Remotion
   потребовал бы тянуть Chrome, а выигрыша в ядре не даёт.
