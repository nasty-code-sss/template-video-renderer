# 0001. Репозиторий публичный, чтобы защитить ветку main

Дата: 16.09.2026
Статус: принято, отступление снято в тот же день

## Контекст

Стандарт разработки требует защиты `main`: запрет прямого пуша, обязательный
pull request, запрет force push.

При первой попытке включить защиту GitHub ответил `403`:

```
Upgrade to GitHub Pro or make this repository public to enable this feature.
```

Защита веток на приватных репозиториях входит в платный план. Репозиторий был
заведён приватным по умолчанию, и какое-то время правило держалось дисциплиной,
а не настройкой: ошибочный прямой пуш в `main` никем не был бы остановлен.

## Решение

Репозиторий сделан публичным, защита `main` включена.

Публичность выбрана не ради экономии: это демонстрационный проект, и открытый код
здесь работает сам по себе, его можно показать ссылкой. Ничего заказчикова,
секретов и персональных данных в репозитории нет, он написан с нуля.

## Что это меняет

1. Прямой пуш в `main` запрещён технически, слияние только через pull request.
2. Код виден всем. Всё, что попадает в коммит, попадает и в публичный доступ,
   поэтому `.env` и любые ключи закрыты `.gitignore` с первого коммита,
   а секретов в конфигах нет: в YAML лежат только имена переменных окружения.
